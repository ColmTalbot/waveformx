Summary

waveformx implements the frequency-domain model IMRPhenomXPNR and the time-domain surrogate NRSur7dq4 in JAX, with the interface of waveformrs's Python bindings and LALSimulation's conventions. Every model is a pure function of a Binary pytree, so it can be compiled with jax.jit, evaluated for many binaries at once with jax.vmap, and differentiated with respect to all twelve parameters of the binary with jax.grad, jax.jvp and jax.jacfwd. LALSimulation's SimInspiralTD and SimInspiralFD are reproduced as well, with LAL's lengths and start times, and are differentiable too. The models follow LAL's code branch for branch, with each branch written as traced arithmetic. They agree with LALSimulation 6.2.0 to rounding for NRSur7dq4, and for IMRPhenomXPNR to the level at which different builds of LAL agree with each other.

Models as pure JAX functions

The package has the interface of waveformrs's Python bindings, with the same function names, keyword arguments, options, result classes and exceptions. Underneath, every model is a pure function of a Binary: a NamedTuple of float64 arrays (or float32 arrays), and so a JAX pytree.

import jax, jax.numpy as jnp, numpy as np
import waveformx as wf

frequencies = np.arange(20.0, 1024.0, 0.125)
hp, hc = wf.polarizations("IMRPhenomXPNR", frequencies, mass_1=36.0, mass_2=29.0,
                          spin_1=(0.4, 0.2, 0.3), spin_2=(-0.2, 0.3, -0.1), f_ref=20.0)

# the pure function, for jit, vmap and grad
model = wf.polarizations_function("IMRPhenomXPNR")          # f(binary, frequencies)
binary = wf.Binary(mass_1=36.0, mass_2=29.0, spin_1=jnp.array([0.4, 0.2, 0.3]),
                   spin_2=jnp.array([-0.2, 0.3, -0.1]), f_ref=20.0)
loss = lambda b: jnp.sum(jnp.abs(model(b, frequencies)[0]) ** 2)
jax.grad(loss)(binary)                                      # a Binary of derivatives
jax.vmap(model, in_axes=(0, None))(binaries, frequencies)    # many binaries at once

# NRSur7dq4 gives the strain times 1e21 (scaled_strain=False: the strain itself)
h = wf.td_polarizations("NRSur7dq4", 1 / 4096, 20.0, mass_1=40.0, mass_2=20.0)
surrogate = wf.td_polarizations_function("NRSur7dq4")       # f(binary, times)
single = wf.Binary(mass_1=jnp.float32(40.0), mass_2=jnp.float32(20.0), spin_1=jnp.zeros(3, jnp.float32),
                   spin_2=jnp.zeros(3, jnp.float32), f_ref=20.0)
hp, hc = surrogate(single, h.times)                         # in float32
h = wf.simulate_td("IMRPhenomXPNR", 1 / 4096, 20.0, mass_1=36.0, mass_2=29.0)

A call goes through four stages:

  1. Checks on the hostThe public functions convert the arguments and run LALSimulation's checks on concrete values (MODEL.validate), outside any JAX transformation. Invalid masses, spins or frequencies, or a precession version LAL would replace while version_fallback=False, raise the exceptions of waveformrs: InvalidParameterError, PrecessionVersionUnavailableError and so on.
  2. A compiled function per configurationThe model method is compiled with jax.jit with the options fixed. WaveformOptions is a frozen dataclass, so it can be a static argument. JAX caches the compiled function per options and array shape, so a sampler that keeps its frequency grid compiles once.
  3. Traced arithmeticInside, nothing branches in Python on the binary. Each of LAL's ifs becomes a jnp.where between branches that are both evaluated, with safe arguments, so that the branch not taken cannot put NaN into the value or the gradient. Loops of fixed length are lax.scan; loops whose length depends on the binary are lax.while_loop. The precession prescriptions are branches of a switch.
  4. Failures as NaNFailures that LAL can only detect while computing, such as a SpinTaylor integration that cannot reach the reference frequency, make the output NaN. The batch functions report those binaries as ModelError in errors and set their rows to zero.

Importing the package enables 64-bit floats (jax_enable_x64), which IMRPhenomXPNR's comparisons with LAL need; both models also run in float32 (section {{sec:xpnr}}, section {{sec:nrsur}}). The thousands of fitted coefficients of IMRPhenomX are not copied by hand. scripts/rust_to_python.py parses the straight-line Rust of waveformrs (its let bindings, arithmetic, fma calls and f64 methods) and emits the same expressions on JAX arrays. scripts/generate_fits.py then writes them into models/xpnr/_generated/. The control flow is written by hand, file by file after LAL's, and each module's docstring names the LAL function it follows.

Each model package defines a MODEL with a fixed contract. A frequency-domain model has validate, polarizations, modes and choose_fd_modes. A time-domain model has validate, td_polarizations, td_modes and polarizations_at, the last of which evaluates the waveform at any given times. The public functions, the batches and the conversions are written once, against that contract.

IMRPhenomXPNR

IMRPhenomXPNR is IMRPhenomXPHM with the phenomenological PNR precession angles, a co-precessing (2,2) mode tuned to numerical relativity, an antisymmetric (2,|2|) contribution and the 122019 release of the higher modes. In LALSimulation it draws on many of the 49 IMRPhenomX source files, together with the SpinTaylor code and GSL. Here it is about 14,800 lines of Python, of which 4,400 are generated fits.

Four prescriptions in one compiled function

LALSimulation chooses the Euler angles by the binary. In-plane spins below 1e-7 give plain IMRPhenomXPHM with the NNLO angles, without the PNR machinery. Below 1e-6, the PNR machinery runs with the NNLO angles (version 102). Otherwise the SpinTaylor angles are used (version 330). Where LAL's SpinTaylor integration fails, it falls back to the MSA angles (223), or to NNLO if the MSA system cannot be set up. Here the decision is a traced index, and the prescriptions are three branches of a switch; versions 102 and 223 of the PNR machinery share one branch, chosen by a traced flag. Under jax.vmap, lax.switch with a batched index would compute every branch for every binary. The model's own switch, cond and while_loop (_transforms.py) instead have batching rules: a branch is computed for the whole batch only if some binary in the batch takes it, and a loop runs to the longest binary in the batch while selecting only its small carry at each iteration.

The SpinTaylor angles

The SpinTaylor angles are the hardest part to make traceable. LAL integrates the orbit-averaged SpinTaylorT4 equations from f_ref backwards to below f_min and forwards to the end of the inspiral. It uses GSL's adaptive RKF45 at tolerances of 1e-12, samples the solution every Δt = 5 / fcut, repeats the end with ten times finer sampling, and passes all the samples, millions for light binaries, to natural cubic splines of α and cos β. Where each run ends, and so how many samples there are, depends on the exact sequence of steps. The JAX version therefore splits the work:

  • The forward and fine runs repeat LAL's adaptive steps one for one in a while_loop (spintaylor/replica.py): GSL's step control, the retries after a failed derivative, the Hermite-like interpolant and the stopping test. The run then ends where LAL's ends, with the same samples. Its derivatives are those of the recorded steps with the step sizes held fixed.
  • The backward run is long and only ends at a frequency, so it is solved with Dormand–Prince 8(5,3) and its seventh-order dense output. The steps are equal increments of u = 1 / (Mω), so each step covers about the same precession angle, and a few hundred steps resolve a whole inspiral to ~1e-12. The step size is a smooth function of the state, so the solution is differentiable. It differs from LAL's samples by LAL's own integration error, ~1e-9.
  • The splines have as many knots as LAL has samples. Up to 8192 knots they are built as GSL builds them. Beyond that, a natural cubic spline at x depends on knots k intervals away only through factors ~(2 − √3)k. It is then evaluated from the 34 knots around x, which gives the same values to ~1e-15 at a cost per point independent of the number of samples.

Reproducing LAL's discrete choices

Much of LAL's code makes decisions on values that are themselves results of iterations or of NaN arithmetic. Each has to be reproduced exactly, or the waveform changes discontinuously:

  • MSA angles. GSL's Jacobi elliptic function and elliptic integral are ported with a fixed number of iterations, and the iterations GSL would not do are masked out. Unlike LAL, which stores the roots of the spin cubic in a shared struct and races on them under OpenMP, every value here is local, so the angles agree with single-threaded LAL.
  • Higher modes. The order of the intermediate amplitude polynomial is lowered when it would cross zero. CrossZeroP5 takes the roots from GSL's gsl_poly_complex_solve, and LAL's indexing of the roots depends on their order, so GSL's balanced companion matrix and Francis QR iteration are ported step for step in while_loops that end where GSL's end.
  • PNR β connection. LAL picks the connection frequencies of β from the turning and inflection points of a cubic. The computation often produces NaN (complex roots, square roots of negative numbers), which LAL's comparisons then treat as false. It is evaluated twice. The first pass uses LAL's arithmetic, NaN included and under stop_gradient, to make the decisions. The second uses finite stand-ins that follow those decisions, to give the values and their gradients. The inflection points are roots from the trigonometric formula, close to an acos of 1, so there LAL's fused multiply-adds are reproduced exactly, giving ~1e-12 rather than ~1e-8.
  • Antisymmetric amplitude. LAL smooths the amplitude ratio with an 81-point moving average computed in place, so each window reads averages it has already written. That is an order-40 linear recurrence. It is evaluated in blocks of 40 values with a triangular solve per block, inside a lax.scan.

Derivatives in forward mode

Loops whose number of iterations is traced, such as the SpinTaylor runs and GSL's QR iteration, can be differentiated in forward mode but not in reverse mode. Reverse mode through the model's many scalar set-up computations also compiles slowly. So _transforms.differentiable makes the model a jax.custom_jvp function. Its rule computes the Jacobian with respect to the parameters that have non-zero tangents, one jax.jvp per parameter, and contracts it with the tangents. The contraction is linear, so jax.grad, which transposes it, works as well as jax.jvp and jax.jacfwd. The Jacobian is itself a custom_vmap function, so under jax.vmap of a gradient the binaries are batched inside the differentiation. Where LAL takes derivatives by finite differences, with steps of 1e-9 and 1e-7 in the intermediate region of the higher modes, the values follow LAL. Their tangents, however, are those of the exact derivatives. The tangents of the finite differences themselves would amplify rounding by up to 1e14.

The parity fix

By default the model includes the fix of lalsuite !2593 from LALSuite's development branch, as waveformrs does. The fix restores the mirror symmetry of the antisymmetric modes: flipping the in-plane spins and taking ι → π − ι gives (h+, −h×). pnr_parity_fix=False, or WaveformOptions.lalsimulation_defaults(), gives the released LALSimulation 6.2.0. Both are compared with LAL in section {{sec:accuracy}}, the fixed model with a LALSimulation 6.2.0 patched with the fix ({{xpnr_patched_build}}).

Making it compile and run faster

The first complete version took about 32 ms per waveform and 2.3 s for jax.vmap over 64 binaries; compiling its reverse-mode gradient took 714 s. A second round of work brought these to about 18 ms, 0.74 s and 132 s (measured during development on this machine). It moved the derivatives to forward mode and added the batch-aware branches and loops. It merged versions 102 and 223 into one branch, computed only the PNR β of the binary's region, chose the intermediate polynomials of all higher modes together, and solved the SpinTaylor equations with the 3-vectors as arrays. The current numbers are in section {{sec:performance}}.

A third round cut the compilation further. Only the SpinTaylor prescription is compiled by default (version_fallback=False). Compile time grows with the number of instructions XLA optimises, and XLA already merges identical computations, so the round looked for code compiled more than once with different inputs. The SpinTaylor splines are now evaluated at all the points the set-up reads in one call, and at the frequencies of the antisymmetric mode together with the PNR grid. The six derivative evaluations of an RKF45 step, the double QR sweep of GSL's root finder and the coefficients of the four higher modes (under jax.vmap, with the mode a traced value) each compile once. The intermediate polynomials of the higher modes come from a small linear solve rather than LAL's closed forms. The co-precessing modes and the factors of the twist pass optimization barriers: XLA had copied their computation into both polarizations and into every column of the Jacobian, which made its fusion pass quadratic for the gradient. Along the way CrossZeroP5 was fixed (section {{sec:differences}}). Measured one at a time during development, tracing, lowering and compiling IMRPhenomXPNR (all modes, 64 frequencies) went from 25 s to 15 s, under jax.vmap from 35 s to 20 s, and its gradient from 115 s to 55 s. The gradient compiles a forward-mode Jacobian, about 3.4 times the instructions of the model, so it stays well above the model.

The same round made the compiled waveform about a quarter faster. XLA's CPU runtime runs a loop body on the calling thread only if the body has at most eight kernels or touches no buffer larger than 512 bytes. Otherwise it hands every iteration's kernels to a thread pool, at a cost of microseconds per iteration. The loop bodies of the SpinTaylor replica and of the DOP853 integration now stay within that limit: each step runs in a one-iteration loop that carries the state itself (_math.isolated_step). The cross products of the SpinTaylor equations use gathers rather than concatenations, which XLA makes a kernel each. The moving average of the antisymmetric amplitude, a triangular solve per block of 40 frequencies, solves one system for all blocks on a uniform frequency grid. Per step, the replica went from 8.5 to 6 µs and the DOP853 integration from 15 to 8.5 µs.

The lean model

The option lean=True (models/xpnr/lean.py) is the extended model of report/extended, with the direct SpinTaylor angles and the parity fix, stripped of the layers that only reproduce LAL's numerical procedure. It is the version meant for further work on speed and for ports to other frameworks. LAL's physics is kept: the fits, the ansatzes, the PNR construction of the angles and the discrete choices of the higher-mode amplitudes. What goes:

  • The SpinTaylor replica. The precession equations are solved once, in one DOP853 loop with dense output (spintaylor/lean.py): backward steps of equal increments of u = 1/(Mω) to below fmin, then forward steps from fref (at most a tenth of u each, which keeps the steps short near v = 1 for large aligned spins) until LAL's stopping conditions are met. There is no RKF45 replay, no sampling lattice, no finer re-run of the end of the inspiral and no second integration from the start of the grid of the PNR interpolants: the one integration starts low enough for that grid. The end of the inspiral is the extended model's: where the first stopping condition is met on the dense output, less half a step of LAL's fine sampling, found by bisection and refined by a Newton step that carries the derivatives.
  • Arithmetic emulation. Masses stay in solar masses, the mixing coefficients of the (3,2) mode are not rounded to single precision, nothing keeps XLA from fusing multiply-adds, and the connection frequencies of the PNR β follow the finite evaluation alone, without replaying LAL's NaN arithmetic. The quintic of the higher-mode amplitudes is tested for a zero crossing by its signs at 257 points instead of GSL's companion-matrix QR iteration.
  • Prescriptions and switches. Only the SpinTaylor angles are compiled; the higher modes take exact derivatives where LAL takes finite differences (as the extended model does), evaluated at one point.

Over {{lean_n}} random binaries drawn as in report/extended, the lean model agrees with the extended model to a largest mismatch of {{lean_vs_extended}} (median at rounding), with the same binaries finite; at special binaries (aligned, single, vanishing and nearly aligned spins, a reference frequency beyond the PN energy test, q = 18, χ = 0.98) the mismatches are at most ~10−12, and its Jacobian agrees with central finite differences to ~10−6 except across the zero of the in-plane spins, where the extended model is discontinuous by design. Against LAL, over {{lean_vs_lal_n}} binaries for which LAL keeps the SpinTaylor angles, the weighted mismatch has median {{lean_vs_lal_median}} and maximum {{lean_vs_lal_max}}, as for the extended model (report/extended). In float32 it agrees with float64 to mismatches of 10−9–3×10−7. Its derivatives are finite in float32 (over 300 random binaries up to q = 30, each mode and the polarizations; before two fixes described below, the derivative of the (2,1) mode was NaN for half of them, mostly above q = 10, and that of every mode for 2%). Measured one at a time (report/lean_xpnr.py: 64 frequencies, all modes, tracing + lowering + compilation), the lean model compiles in {{lean_compile_eval}} against {{default_compile_eval}} for the default model, under jax.vmap in {{lean_compile_vmap}} against {{default_compile_vmap}}, and its gradient in {{lean_compile_grad}} against {{default_compile_grad}}; at the benchmark binary it runs in {{lean_runtime}} against {{default_runtime}} (the extended model: {{extended_runtime}}).

A reference frequency scaled by the mass

LAL gives the spins, the inclination and φref at a reference frequency fref in Hz, by default the first frequency, and requires fmin ≤ fref ≤ fmax for the PNR angles. The SpinTaylor angles are needed over the band of (2,2)-equivalent frequencies 2f/m′ of the modes, and LAL starts that band at 2fmin/MMAX, with MMAX the largest m′ requested. For the (2,1) mode alone the band starts near 2fmin, above a reference at fmin: LAL leaves the SpinTaylor angles (for the MSA angles) and the default, extended and lean models give NaN. Of {{ref_n}} random binaries (q ≤ 30, 3–400 solar masses, spins ≤ 0.99, bands from 10–30 Hz), the lean model with fref = fmin is finite for {{ref_finite_lal_21}} with the (2,1) mode alone and {{ref_finite_lal_all}} with all modes.

The option reference_mf of the lean model gives the binary at fref = reference_mf/M instead, the same point of the inspiral for every binary; Binary.f_ref must then be zero (the public functions raise an error otherwise, the pure functions give NaN, and the derivative with respect to it is zero). The recommended value, REFERENCE_MF = 0.01, lies before the end of the inspiral for every binary: with the spins given there, the PN energy test ends the inspiral at Mf ≥ 0.015 for q ≤ 30 and spins ≤ 0.99 (the worst case: q = 30, both spins −0.99 along L), so the reference is at most 2/3 of the way there, below the hand-off of the SpinTaylor α to its merger-ringdown continuation at 0.97 of it. What changes (pnr.common_setup, pnr.interpolation_grid):

  • The band of the angles reaches the reference. All quantities are (2,2)-equivalent frequencies, and the minimum is taken after the scaling by 2/m′. The grid of the PNR interpolants holds the bands of the requested modes only (LAL's always holds the (2,2) band, below the integration where m′ = 1 alone), extended by soft minima and maxima (C2 blends a node wide) to hold fref with at least four nodes on each side; for heavy binaries, whose spacing is a sizeable fraction of the frequency, the spacing is at most fref/8. The integration starts below min(LAL's start, 0.25 fref), again by a soft minimum, and at 0.25 fref where LAL's start is not positive (heavy binaries with m′ = 1 or 3 alone).
  • Everything else follows from fref. The phase alignment of the (2,2) mode, the line of sight, the J frame, the offsets of α and ε and the PNR splines at the reference read the waveform struct's fref, so they move with it. The LAL-convention lean model and the default model are unchanged (static branches).

With the mass-scaled reference the lean model is finite for at least {{ref_finite_scaled_min}} of the {{ref_n}} binaries for every mode array ((2,1), (3,2), (3,3), (4,4) alone, and all modes), and its gradients are finite in float32 and float64. Along the total mass across the masses where fref crosses the lower end of the band (~200 solar masses for all modes at fmin = 20 Hz, ~50 for the (2,1) mode alone) the overlap shows no jump (fifth differences within 8 times their noise) and the forward-mode derivative agrees with finite differences to 2×10−3. In float32 the waveform agrees with float64 to mismatches below 3×10−6, and the gradients are as close to float64 as with LAL's convention. Converters. to_mass_scaled_reference and to_physical_reference (models/xpnr/reference.py) map a binary between the conventions by integrating the lean model's SpinTaylor equations between the two references (4096 DOP853 steps in u = 1/(Mω)), as pure functions (jit, vmap, grad). They keep the spins, L and the line of sight. The frame at the new reference is the one the equations carry along, turned about L by the orbital phase between the references, taken from IMRPhenomXAS's (2,2) phase, by which the model's alignment of the phase moves. With that turn, aligned-spin binaries give the same waveform in both conventions (mismatch ~10−11 without maximisation), and round trips return the binary to ~10−14. The orbital phase is thousands of radians for light binaries, so in float32 the converted spins and angles are good to ~10−4: convert in float64. The basis of the polarizations follows L at the reference, so the two descriptions differ by a rotation of the polarizations, which the converters return.

For precessing binaries the conventions differ by more than numerics, because IMRPhenomXPNR itself depends on where the reference lies: it takes the aligned spins of the co-precessing modes, J and the parameters of its fits at the reference. Over {{ref_lal_n}} binaries drawn at 20 Hz (q ≤ 12, 20–90 solar masses, spins ≤ 0.9) and converted to 0.01/M (inside the band), LAL with the parity fix at the two references differs by a mismatch of median {{ref_lal_vs_lal_median}} and maximum {{ref_lal_vs_lal_max}} (above 10−3 for {{ref_lal_vs_lal_above}}), maximised over time and phase. The lean model with the mass-scaled reference agrees with LAL given the converted binary at fref = 0.01/M to a median of {{ref_lean_vs_lal_median}} and a maximum of {{ref_lean_vs_lal_max}}, as closely as the lean model agrees with LAL in its own convention. As the in-plane spins vanish, the waveforms of the two conventions converge (mismatch 4×10−5 at χp = 0.3, 10−8 at 0.01). A converted binary therefore stands for the same physical system, but a waveform model whose reference moves is a different waveform for precessing binaries, by as much as LAL's own dependence on fref.

A reference-invariant model. The lean model with the mass-scaled reference removes that dependence: whatever its reference_mf, it first carries the binary to the canonical reference REFERENCE_MF = 0.01 (reference.to_canonical, the converter's integration with a step count fixed by the two references, so the MLX port takes it too), and the rest of the model runs as at 0.01. The aligned spins of the co-precessing modes, J, the parameters of the PNR fits, the offsets of the angles, the alignment of the phase, the line of sight and the basis of the polarizations are then all taken at 0.01. Reading the state at 0.01 from the model's own SpinTaylor solution instead would be circular, since the start and end of that integration and the grid of the PNR interpolants follow from the aligned spins at the reference. The converters pass through 0.01 too, with the orbital phase of both legs from the aligned spins there, so conversions compose. A binary converted between two references (0.006 and 0.012, 0.01 and 0.008, 0.01 and 0.002; precessing, nearly aligned and aligned) gives the same waveform without any maximisation, to a largest relative difference of 10−13 (10−7 at q = 18, whose integration takes few steps), in float64, float32 and MLX; without the conversion the waveform changes by order one. Before this, the lean model at two references differed by mismatches of 10−5–2×10−2, as LAL does. Two checks show that this is the model's construction and not the converter. The converter's evolved spins, L and E1 agree with the lean model's own SpinTaylor solution to 10−13 (10−8 for q = 18), and with LAL's SimInspiralSpinTaylorPNEvolveOrbit to 10−9. With reference_mf = 0.01 nothing changes. Single precision

IMRPhenomXPNR is evaluated in the precision of the binary's parameters, as NRSur7dq4 is, and returns the strain times 1021 unless scaled_strain=False. The comparisons with LAL use scaled_strain=False. A float32 binary is evaluated without promoting any float32 value to float64. Python constants in LAL's expressions remain weakly typed float64 scalars, which take float32 when they meet the data; tests/test_xpnr_float32.py checks the waveform, its forward derivative and its gradient. The changes that made float32 work change the float64 waveform by rounding only:

  • No SI round trips. In float64 the masses still pass through kilograms as in LAL. In float32 they stay in solar masses (_math.mass_unit), because XLA folds the square of the solar mass in kilograms into the derivatives, as it did for NRSur7dq4. The amplitude takes the distance in Mpc. Two expressions of LAL that XLA rewrites into powers beyond float32's range are written another way: the velocity of the chirp-time bound, where XLA turned a division by c into a multiplication by c8, and the arctan window of the PNR β, whose 500th powers overflow. The 500th power in that window, below 1.5 for β in [0, 0.01], exceeds float32's range where the ringdown β of the fits is below −0.3 rad (large mass ratios with in-plane spins): its value is finite but its derivative was NaN, so there it is computed as π/2 − arctan of the inverse power, the same function to rounding. The pseudo-PN coefficients of the higher-mode inspiral amplitudes divide by a product of powers of the collocation frequencies, ~10−19 for the (2,1) mode at Mf ~ 0.01, whose square in the derivative of the quotient falls below float32's range (NaN derivatives of the (2,1) mode, mostly above q = 10); the coefficients do not depend on the scale of the frequencies, and are computed in units of the end of the inspiral.
  • Constants of the precision. Machine epsilon, the smallest normal number and the floors of safe square roots (10−300 in float64) follow the precision. The tolerances of the RKF45 replica (10−12, below float32's rounding) become 10−5, and the higher modes take exact derivatives instead of LAL's finite differences with a step of 10−9.
  • Types from the binary. Default float and integer types, numpy coefficient tables and the counts of loops follow the precision (_math.real, _math.integer), since an int64 count or a float64 table promotes float32 data to float64.

The extended model in float32 agrees with its float64 waveform to a mismatch of ~10−9–10−7 for the binaries tried, and its gradients agree to ~10−4. The default model replays LAL's adaptive RKF45 steps and samples them on LAL's time lattice. In float32 its waveform differs from float64 by mismatches of 10−5–10−2, so float32 is meant for the extended model. Running JAX's float64 switch off inside a trace (jax.enable_x64(False)) would have avoided most of the type changes, but JAX caches the conversions of numpy constants and the executables of eager operations without regard to that switch, so a float32 evaluation corrupted later float64 ones in the same process.

The lean model on Apple GPUs with MLX

waveformx.models.xpnr.mlx runs the lean model in MLX on the GPU of Apple silicon, in float32: polarizations(binary, frequencies) for one binary or a batch (shared or per-binary frequencies), differentiable with mx.grad, and polarizations_and_jacobian. It is not a second implementation of the model. The lean model is cut into stages that are functions of one binary's scalars (the set-up: four stages of 7–41 thousand scalar operations) or of its scalars and one point (the PNR angles at a grid point, the angles, modes and twist at a frequency). Each stage is traced to a jaxpr in float32 and lowered (mlx/_program.py) to straight-line code on scalars: arrays of static shape become arrays of scalars, loops of static length are unrolled, branches are computed both ways and selected, the small linear solves (LAPACK's getrf with partial pivoting) and sorts are written out, complex numbers become pairs, and what does not depend on the inputs is computed once. The code runs as a Metal kernel over the batch and the points, its derivatives from the JVP that JAX writes, one thread per binary, point and direction. Products added once are fused into multiply-adds, as XLA's CPU backend fuses them: without this, the float32 fits of the PNR β and the collocation solves of the higher modes came out 20–100 times further from float64 than JAX's float32. The rest is written for MLX: the SpinTaylor integration (a Metal kernel, one SIMD group per binary with a lane per component of the state, calling the translated derivatives), the searches in its dense output, the natural splines of the PNR interpolants (the inverse of the tridiagonal matrix as a filter of the second differences), Boole's integral of γ and the moving average of the antisymmetric mode.

The derivatives are forward-mode Jacobians with respect to the twelve parameters, contracted with the cotangents in a custom VJP, as the JAX model contracts its own. One choice differs from JAX's float32: the Newton step at the end of the inspiral takes the exact derivative of the stopping conditions in time, where JAX takes the secant of the bisection's bracket, which float32 does not resolve. JAX's float32 derivative of the end of the inspiral is off by up to 90% for the binaries tried; the MLX one agrees with float64 to ~10−6.

IMRPhenomXAS

IMRPhenomXAS, the aligned-spin (2,2) mode of IMRPhenomX, is a public approximant ("IMRPhenomXAS") and has an MLX version (waveformx.models.xas.mlx). Both are written for the cases it is mostly called in: non-uniform grids of up to about a thousand frequencies, often many binaries at once, and long uniform grids.

A table per binary, a short formula per frequency

The coefficients come from IMRPhenomXPNR's (2,2) mode (models/xpnr/internals.py, amp22.py, phase22.py), so the fits, collocation systems and connections are LAL's. models/xas/core.py then rewrites the model in powers of the frequency in Hz. In each of the three regions of the phase, LAL's sum of powers of Mf and their products with log Mf becomes a sum over 16 powers of f (at most 13 per region), with the powers of M folded into the coefficients and log Mf = log M + log f. LAL's time shift and its reference phase (but for the part of the leading term, below) fold into the same coefficients. The amplitude becomes a polynomial in f1/3, a rational function and an exponential. Each binary then has a table of {{xas_table_size}} numbers, and a frequency needs only its own powers. In a batch with shared frequencies (jax.vmap) those powers are computed once, and per binary and frequency what is left is one region's sum, the arctangent and exponential of the merger, and a sine and cosine. The JAX model is one elementwise expression with the regions selected, without the stacked arrays and reductions of a first version, which took twice as long on long grids. Its derivatives are JAX's own, in either mode.

Three changes from LAL's arithmetic make float32 and float64 compute the same thing. Both work in solar masses rather than LAL's round trip through kilograms. LAL's quasi-normal-mode fits are ratios of polynomials in the final spin whose numerator and denominator both nearly vanish at af = 1. In float32 that cancellation loses a part in 104 of the ringdown frequency at af = 0.9 and up to 1% near 1, so the fits are evaluated in powers of 1 − af, with coefficients re-expanded in float64. In float64 they differ from LAL's form by up to 10−11, LAL's own rounding. The third change, the leading term of the phase, is described below. One fix reaches IMRPhenomXPNR too: the peak frequency of the ringdown amplitude took sqrt(1 − γ22) in the branch not taken for γ2 > 1. That gave NaN reverse-mode gradients (XPNR's forward-mode Jacobians did not see it), and the square root is now guarded as the others are, in scripts/generate_fits.py.

float32 and binary neutron stars

From 20 Hz the inspiral phase of a binary neutron star reaches ~104 radians, where one float32 ulp is ~10−3 radians. Summing the phase in float32 lost about ten ulps, from the rounding of the coefficient of f−5/3, of the reference phase that cancels it and of the power itself. Light binaries then had mismatches of 10−5–10−4 against float64. The leading term is now separate. Its coefficient is T0 = K0 M1/3 / (m1 m2), its value at the reference frequency is A, and T0 f−5/3 − A, its sum with the rest and the reduction to [−π, π] are computed in extended precision. JAX uses float64, which the package always enables; Metal uses double-float pairs of floats, with sums and products made exact by fused multiply-adds. Every other term stays below ~103 radians and is computed in the working precision, as are the derivatives.

IMRPhenomXHM

IMRPhenomXHM, IMRPhenomXAS with the (2,|1|), (3,|3|), (3,|2|) and (4,|4|) modes, is a public approximant ("IMRPhenomXHM") with an MLX version (waveformx.models.xhm.mlx), written as IMRPhenomXAS is: tables per binary, a short formula per frequency. It returns the spherical-harmonic modes as well as the polarizations.

One code path

Where LALSimulation offers several versions, only its defaults are implemented: the 122022 release with recalibrated amplitudes (PhenomXHMReleaseVersion; IMRPhenomXPNR uses 122019), the default inspiral, intermediate and ringdown versions of each mode, and no multibanding (LAL's default for uniform grids, which interpolates the modes to ~10−4). The modes are those of the polarizations (IMRPhenomXHM_MultiMode2): the (3,2) mode recycles the (2,2) mode in its ringdown and the higher modes are not cut at 0.3/M, where LAL's one-mode functions differ. Mode arrays are not supported. The 122022 amplitudes are new code (their fits generated from waveformrs into _generated/hm_amp_fits_*.py); the phases reuse the higher-mode code of IMRPhenomXPNR (models/xhm/reference.py is LAL's computation in Mf, core.py the tables).

Four changes from LAL keep float32 and float64 one computation. The derivatives LAL takes by finite differences (the inspiral and ringdown amplitudes at the boundaries of the intermediate region, with a step of 10−9; the first and second derivatives of the rotated (3,2) ringdown phase that fix its intermediate phase, with a step of 10−7) are exact. LAL's second difference amplifies rounding by ~1014, so its (3,2) differs from the exact one by a mismatch of {{xhm_lal_32_median}} (median; at most {{xhm_lal_32_max}}); waveformrs reproduces LAL's values bit for bit, so they are LAL's. The QNM and mixing fits of the higher modes are in powers of 1 − af, as for the (2,2), and the mixing coefficients are kept in the working precision (LAL rounds them to single precision, which made the waveform a staircase in the parameters). Two ill-conditioned collocation systems, the intermediate amplitude (up to eight coefficients) and the intermediate phase of the (3,2) (a quartic in 1/f), are solved for the same polynomials in variables centred on their regions. The pseudo-PN amplitude coefficients come from the inverse of their constant system rather than LAL's closed form, whose small products underflow in the derivatives in float32.

The phase of every mode is that of the (2,2) rescaled in the inspiral, aligned with it at low frequency, and in the ringdown of the (3,2) a rotation of the (2,2) and the spheroidal (3,2). The large reference phase of the (2,2), ~104 radians for binary neutron stars, enters all of them through that alignment and rotation; it is taken out exactly ((m/2) T0 (2f/m)−5/3 is the leading term of mode m), so each mode is (m/2)8/3 T0 f−5/3 − (m/2) A plus a phase of at most ~103 radians, and the first part is computed in extended precision as for the (2,2).

On Apple GPUs with MLX

The set-up is five generated kernels run side by side, one for the (2,2) and the factors of the modes, one per higher mode. The waveform at the frequencies is a kernel written by hand that calls a function generated from each mode's formula, with the leading terms in double-float. The Jacobian takes the forward-mode derivatives of the tables and of these functions, eight directions at once. That costs about ten times the waveform, where forward mode cost fifty times. TaylorF2 and IMRPhenomD

TaylorF2 and IMRPhenomD are public approximants ("TaylorF2", "IMRPhenomD") with MLX versions (waveformx.models.taylorf2.mlx, waveformx.models.phenomd.mlx), written as IMRPhenomXAS is: a table of coefficients per binary, a short formula per frequency, the leading term of the inspiral phase in extended precision. They are ported from waveformrs (src/taylor.rs, src/pn.rs, src/imrphenomd/) and checked against LAL.

TaylorF2 has LAL's defaults: the 3.5PN phase with every aligned-spin term, the leading-order amplitude and no tidal terms. Its phase is LAL's sum over powers of v = (πMf)1/3 and their products with log v, written in powers of f in Hz (eight terms but for the leading one) with the powers of M folded into a table of {{tf2_table_size}} numbers. Its post-Newtonian phasing (models/taylorf2/pn.py) is shared with IMRPhenomD. As in LAL's SimInspiralChooseFDWaveformSequence, every frequency is evaluated, without the cut at the innermost stable circular orbit of LAL's uniform grid, and f_ref = 0 refers the phase to coalescence. Over {{tf2_lal_n}} random binaries (as for IMRPhenomXAS, to the Schwarzschild ISCO or 2048 Hz) it agrees with LAL to {{tf2_lal_max_rel}} at most (median {{tf2_lal_median_rel}}), mismatches below {{tf2_lal_max_mm}}: rounding, mostly of the ~104 radians of the phase of light binaries.

IMRPhenomD has three regions each in its phase and amplitude. The inspiral phase is TaylorF2's (without the 3PN spin-spin term, which IMRPhenomD was not calibrated with) and four pseudo-PN terms; the intermediate phase is a sum of powers and a logarithm; the merger-ringdown phase adds an arctangent. The amplitude is a polynomial in f1/3, a quartic and a Lorentzian times an exponential. The table has {{pd_table_size}} numbers. Three things differ from LAL. The masses are in solar masses and are not reordered (the fits are symmetric under the exchange of the bodies), so the waveform is smooth through equal masses. The quartic of the intermediate amplitude is solved for in powers of Mf/Mfpeak, better conditioned in float32. And the quasi-normal-mode frequencies come from closed-form fits (below). Where LAL drops a square root of the peak frequency (γ2 > 1), its argument is kept positive in the branch not taken, so that the derivatives stay finite.

The quasi-normal-mode frequencies

LAL interpolates the ringdown and damping frequencies of the (2,2) mode in the final spin a with a natural cubic spline through 1003 tabulated values (QNMData_a, QNMData_fring, QNMData_fdamp, given to six or seven digits). waveformx replaces the spline with Chebyshev series of degree {{pd_qnm_degree}} in ((1 − a)/2)1/3: the frequencies vary like powers of 1 − a near a = 1, where the damping frequency vanishes, and the cube root makes them smooth. Rational functions in the same variable and in (1 − a)1/2 were tried too; their fits were less accurate and some had poles in the range. scripts/fit_phenomd_qnm.py fits the series to the relative error, with weights reduced for points far off the others, and writes models/phenomd/_qnm_fit.py. The error of LAL's spline is estimated by leaving out each point of the table and evaluating the spline through the others there. That is the interpolation error at twice the spacing, an overestimate where the frequencies are smooth, together with the noise of the table, which the spline passes through.

NRSur7dq4

NRSur7dq4 interpolates numerical-relativity waveforms of precessing binaries. It was trained on mass ratios up to 4 and spin magnitudes up to 0.8, and LAL allows it to extrapolate beyond those. It integrates an ODE for the coprecessing frame, the orbital phase and the spins, with time derivatives given by fits at 233 nodes. It then evaluates the coorbital modes from fits at their empirical-interpolation nodes and rotates them to the inertial frame. The JAX version follows LALSimIMRPrecessingNRSur.c and waveformrs's translation of it.

  • Data. The 17 MB HDF5 file is read once with h5py. Every dynamics fit becomes a dense row over the union of the monomials the fits use, so the nine fits of a node are one matrix–vector product. The fits of the waveform nodes are stored by the order of their mass-ratio monomial, so the mass ratio, which is the same at every node, is folded into the coefficients once per binary.
  • Dynamics. LAL steps from the reference frequency to the nearest node, takes three RK4 steps (forwards or backwards, depending on that node), and covers the remaining nodes with fourth-order Adams–Bashforth steps in both directions. Since the starting node depends on the binary, the integration is one lax.scan of fixed length. It walks backwards from the start and then forwards, evaluating the fits of one node per step as LAL does. The Adams–Bashforth weights depend only on the node and are tabulated once.
  • Splines. GSL's natural cubic splines solve a tridiagonal system whose matrix depends only on the knots. As in waveformrs, it is factorised once when the data are read, so fitting a spline needs only the two substitution sweeps.
  • Frame rotation. LAL's Wigner D-matrices use negative powers of the quaternion's components, with special cases where they vanish, as they do for spins along the orbital angular momentum. Here the negative powers are cancelled analytically, which makes each element a polynomial in the quaternion: the same values, no special cases, and finite gradients in the non-precessing limit.
  • Output grid. The number of samples depends on when the orbital frequency reaches π fmin, so it is found on the host. A compiled pass evaluates the frequency fits, and numpy repeats LAL's search operation by operation. The waveform is then computed on a power-of-two buffer of at least 256 samples, which waveforms of similar length share, and trimmed to the binary's length.

polarizations_at(binary, times) evaluates the waveform at any times relative to the peak. It is pure and differentiable with respect to every parameter, including f_ref, which moves the reference time and so the frame. It is what jax.vmap, jax.grad and the conversions use.

Single precision and the scale of the output

NRSur7dq4 is evaluated in the precision of the binary's parameters. A Binary of float32 arrays is evaluated in float32 throughout, with a float32 copy of the data cast from the float64 arrays (the spline factorisations included). A test checks that no operation of the traced waveform, or of its gradient, is in float64. The public functions take Python numbers, so they stay in float64. Two changes make float32 usable:

  • The output is the strain times 1021. This applies to every NRSur7dq4 function, the public functions and the conversions included, unless scaled_strain=False. The strain itself fits in float32, but its square (~10−42) and a detector's power spectral density (~10−47) do not. The comparisons with LAL in this report use scaled_strain=False.
  • Nothing passes through SI units. LAL converts the masses to kilograms and back (m * MSUN_SI / MSUN_SI) and works with the distance in metres. In float32, XLA folded the square of the solar mass in kilograms (~4×1060, beyond float32's range) into the derivative of the mass ratio, so the compiled gradient was NaN. The derivative with respect to a distance of ~1025 m underflowed to zero. The masses now stay in solar masses, and the amplitude is one constant times the total mass over the distance in Mpc. In float64 this changes the waveform by rounding only.

What float32 costs in accuracy was measured on {{f32_pairs}} pairs of binaries, drawn as for the accuracy comparison (report/float32_nrsur7dq4.py). {{f32_pairs_each}} pairs are two independent binaries, whose overlaps are near zero. The other {{f32_pairs_each}} are a binary and a small perturbation of its masses, spins and angles, with a median overlap of {{f32_nearby_overlap}}. Both binaries of a pair are evaluated on one time grid, in float64 and in float32, projected on a detector and tapered at the start. Inner products use the aLIGO design sensitivity from 20 Hz, without maximisation, and are computed in float64 unless stated otherwise.

On Apple GPUs with MLX

waveformx.models.nrsur7dq4.mlx is NRSur7dq4 in MLX, Apple's array library, which runs on the GPU of Apple silicon. It is an optional dependency (pip install waveformx[mlx]). The module is separate from the JAX code, which it leaves unchanged, and reads the same data through the JAX loader. It provides:

  • the pure functions polarizations_at and modes_at;
  • LAL's waveforms on its grid: td_polarizations, td_modes and batch_td_polarizations;
  • the conditioned waveforms: simulate_td, simulate_fd and their pure functions.

Everything is float32 and differentiable with mx.grad. The pure functions take one binary or a batch along a leading axis. MLX has no float64 on the GPU and no scan, while_loop or cond. Its vmap and forward-mode derivatives do not pass through custom kernels. So:

  • Splines as matrices. The JAX version fits its splines with two substitution sweeps (a lax.scan). The knots are fixed, so each spline is a fixed linear map, computed in float64 when the data are read:
    • the spline of the dynamics states, evaluated at the waveform's times, is one 2000 × 230 matrix;
    • the second derivatives of the spline through the polarizations are the inverse of its tridiagonal system applied to the right-hand side.
    For a batch, each map is one matrix product over all the binaries.
  • The dynamics in one Metal kernel. The 230 sequential RK4 and Adams–Bashforth steps run in a hand-written Metal kernel, with one SIMD group per binary and one state component per lane. A second kernel carries dual numbers through the same steps. It gives the Jacobian of the states with respect to the mass ratio, the spins and the reference time, and the kernel's VJP contracts that Jacobian.
  • The frame rotation in Metal kernels. The Wigner rotation of every mode sample is a generated kernel. Its VJP is a kernel too: it differentiates with respect to the quaternion through the generators of the rotation, using D(pq) = D(p) D(q).
  • Harmonics as Fourier series. The spin-weighted harmonics are trigonometric series in the inclination, with coefficients computed once in float64. Evaluated directly, the powers of cos(θ/2) and sin(θ/2) in the gradient were fused by mx.compile into a kernel with more arguments than Metal allows.
  • LAL's grids on the host. The lengths and epochs are computed in float64, as the JAX driver computes them. A batch is set up all at once: the frequency fits of every binary in one call, then LAL's search in numpy over the batch. This takes {{mlx_batch_grids}} for {{mlx_batch_n}} binaries, against ~0.15 ms per binary one by one. A binary that LAL refuses is set up again on its own, which raises LAL's error. Time and frequency domains

simulate_td and simulate_fd reproduce LALSimulation 6.2.0's SimInspiralTD and SimInspiralFD. IMRPhenomXPNR can be given in the time domain and NRSur7dq4 in the frequency domain, and each model can also be conditioned in its own domain. They follow waveformrs's src/conversions/ and src/conditioning.rs.

LAL's conditioning starts the model below the requested frequency by an amount set by bounds on the chirp time, merger time and ringdown time. It tapers the extra length, applies a Butterworth high-pass filter, shifts the waveform in time and crops it to a length and epoch derived from the same bounds. The work is split by what needs to be exact:

  • On the host, in Python floats. The lengths, shifts, taper widths and GPS epochs are computed with LAL's arithmetic. This includes C's pow, cbrt and round, and the fused multiply-adds of clang's arm64 build, reproduced exactly through rational arithmetic. As a result, lengths and epochs are LAL's bit for bit.
  • In JAX, pure and differentiable. The bounds are computed again where the waveform depends on them continuously: the starting frequency given to the model and the cutoff of the first high-pass filter. So do the filter coefficients, the filter itself (a lax.scan of LAL's recursion per second-order section), the tapers and the Fourier transforms. Arrays have fixed, power-of-two lengths, so one compilation serves many binaries.

IMRPhenomXPNR smooths its antisymmetric amplitude with a moving average over the array of frequencies, which LAL takes over its band. To keep one array length per transform length, the model is evaluated on the band, followed by frequencies just above it and then the band's last 82 frequencies again. The first L − 41 values are then averaged as LAL averages them, and the last 41 are taken from the end. simulate_td_function and simulate_fd_function return the conversion as a pure function. It keeps the lengths, shifts, tapers and epoch of a reference binary, while the starting frequencies and filter cutoffs follow the binary, so the gradient includes their dependence on the masses and spins.

The tests show where the difference comes from. The (2,2) mode alone, with its PNR angles and antisymmetric part, agrees to ~1e-9. The higher modes agree to ~1e-5, as different builds of LAL agree with each other. LAL fixes the intermediate amplitude of each higher mode with a fourth-order finite difference of the inspiral amplitude, with a step of 1e-9, which turns rounding of 1e-16 into ~1e-7 in the derivative. It fixes the intermediate phase of the (3,2) mode with a second derivative of a phase of up to 1e4 rad, by central differences with a step of 1e-7, amplifying rounding by ~1e14. Without fused multiply-adds, which JAX does not expose portably, the JAX arithmetic rounds differently from LAL's arm64 build, and these finite differences turn that into a visible difference. Neither value is more accurate than the other. The errors grow with the total mass, where the merger and ringdown, and so the higher modes, carry more of the band: the median is {{xpnr_median_light}} below 20 M☉ and {{xpnr_median_heavy}} above 150 M☉. The largest errors, a few 1e-5, are for heavy binaries with in-plane spins near 0.9. {{xpnr_frac_1e5}} of the draws exceed 1e-5.

With the parity fix, the model agrees with LAL 6.2.0 patched with lalsuite !2593 to {{xpnr_fix_max_rel}} (median {{xpnr_fix_median_rel}}, mismatch ≤ {{xpnr_fix_max_mm}}, over {{xpnr_fix_n}} draws). On the same draws waveformrs agrees with that patched library to {{xpnr_rs_fix_max_rel}}. {{xpnr_failure_text}}

Derivatives

For each model and four binaries, every column of the Jacobian (jax.jacfwd) is compared with central finite differences of the compiled model. The error of a column is max |Ji − Di| / max |Ji| over the frequencies or times and both polarizations. The finite difference is the better of a second-order difference with a step of 1e-6 and a fourth-order difference with a step of 1e-4, both relative for the masses, the distance and fref. The first is limited by rounding, the second by the model's discontinuities.

{{gradients_figure}} {{gradient_table}}

The derivatives are those of the function JAX computes, which is smooth almost everywhere but not everywhere. Wherever LAL makes a discrete choice that depends on the binary, the waveform is continuous only up to the size of that choice's effect, and the derivative is that of the branch taken. Such choices include the number of SpinTaylor samples, where LAL's adaptive integration stops, the node where NRSur7dq4's integration starts, the precession prescription, and the order of the intermediate polynomials of the higher modes. In IMRPhenomXPNR the SpinTaylor waveform jumps by about LAL's integration error, ~1e-9 relative, wherever the number of samples changes. A finite difference that straddles such a jump is wrong by the jump divided by the step, which is why small steps are used. The spins are the parameters that move the precession most, and they show the largest disagreements. For nearly aligned in-plane spins the waveform is also far from linear on the scale of the step. None of this affects the derivatives themselves, which are those of the smooth pieces.

One case is not a jump but a point where no derivative exists. After every step of its dynamics, NRSur7dq4 rescales each spin to its initial magnitude (LAL's PrecessingNRSur_normalize_y). For a body with no spin, an infinitesimal spin then evolves by a factor that depends on its direction, not only on its size. The waveform therefore has a cone-shaped kink in that body's three spin components: one-sided finite differences tend to different values, and no step size makes them converge. At such a point the JAX derivative is finite, as the transform tests require, but it is a convention rather than a derivative. The table reports these components apart. As soon as a body has any spin, even an aligned one, its derivatives agree with finite differences as for the other binaries.

IMRPhenomXPNR: under investigation. For the full IMRPhenomXPNR waveform, the finite differences disagree with the derivatives by up to {{xpnr_gradient_worst}}, by far the most in the in-plane spins. The transform tests, which compare the gradient of a weighted sum of the (2,2) mode with finite differences, agree to ~1e-7. The likely cause is in the higher modes. Their intermediate region is fixed by LAL's finite differences with steps of 1e-9 and 1e-7, which leave rounding noise of ~1e-8 in the waveform. That noise is not smooth in the parameters, so a parameter step of 1e-6 sees a slope of up to ~1e-2 relative from it alone, while the JAX tangents are those of the exact derivatives. If so, the derivatives are right and the finite differences are not. The check still to run: the (2,2) mode alone, and the full model with larger steps, where that noise matters less.

Differences from LALSimulation

  • Rounding, not bit-identity. waveformrs reproduces LAL bit for bit on macOS arm64, using the fused multiply-adds that clang emits. JAX has no portable fused multiply-add and XLA reorders arithmetic, so waveformx agrees with LAL to rounding (NRSur7dq4, the (2,2) mode of IMRPhenomXPNR) or to the rounding amplified by LAL's own finite differences (the higher modes, ~1e-5). Only on the host, where the conversions' lengths and epochs hinge on the last bits, are LAL's fused multiply-adds reproduced exactly. The inflection points of the PNR beta, roots of a strongly cancelling cubic, agree with LAL's to ~1e-9 (relative), which moves its connection frequencies by as much: the waveforms change by a mismatch of ~1e-16.
  • SpinTaylor backward integration. The integration from f_ref down to f_min is a dense Dormand–Prince solution, not LAL's RKF45 steps. It differs from LAL's samples by LAL's integration error (~1e-9).
  • The zero crossings of the quintic intermediate amplitude. LAL's CrossZeroP5, which decides whether a higher mode's intermediate amplitude drops from a fifth-order polynomial, reads shifted entries of GSL's packed roots. It misses some roots and depends on the order in which GSL finds them, which rounding can change. Here every root is tested with its own real and imaginary parts (hm/roots.py), so the order does not matter and GSL's QR steps can work on whole rows and columns. The quick tests are unchanged (IMRPhenomXPNR against LAL: relative error 3.5e-7, mismatch 4.5e-14; the extended (2,2) mode: mismatch 2.9e-8, as before). Of 200 random binaries, none changes with the default options and one changes with the extended angles (mismatch 5.8e-8). Among the single-mode tests, one binary takes another polynomial for its (3,−3) mode, which then differs from LAL by a mismatch of 4.4e-7.
  • Values where LAL divides by zero. At isolated points of the parameter space, LAL's MSA formulas divide by an exact zero and produce inf or NaN. Here the values there are finite, and so are the gradients nearby, for example at equal masses or for a single spin.
  • No multibanding. LAL's SimInspiralChooseFDWaveform uses multibanding by default for IMRPhenomXPNR; waveformx, like waveformrs, evaluates every frequency. SimInspiralChooseFDWaveformSequence has multibanding off, and the conversions are compared with it off.
  • IMRPhenomD's quasi-normal-mode frequencies. They come from closed-form fits in the final spin rather than LAL's spline through its table: they differ by about a part in 106 and change the waveform by mismatches of 10−9 or less (section {{sec:phenomd}}).
  • No data race. LAL's MSA and PNR angles race under OpenMP. waveformx agrees with single-threaded LAL.
  • The scale of the output. Both models return the strain times 1021, and compute the amplitude without SI intermediates (NRSur7dq4 the masses too), which changes their float64 values by rounding. scaled_strain=False, which WaveformOptions.lalsimulation_defaults() also sets, gives LAL's scale.
  • Two options that are not LAL's defaults. With version_fallback=False the compiled model contains only the SpinTaylor prescription and is NaN where LAL would switch to the MSA or NNLO angles. With extended_spintaylor=True it is a different model: the SpinTaylor angles for every binary, with LAL's discrete switches made continuous. A separate report, report/extended, maps where the SpinTaylor angles fail and describes and validates the extended model.

Limitations and future work

  • Six approximants. Only TaylorF2, IMRPhenomD, IMRPhenomXAS, IMRPhenomXHM, IMRPhenomXPNR and NRSur7dq4 are public; IMRPhenomXP and XPHM with their own flags are not exposed. TaylorF2, IMRPhenomD and IMRPhenomXAS have their polarizations at given frequencies only, not their modes or LAL's uniform grids; none has the conversions, nor in MLX LAL's errors (they give NaN). TaylorF2 has LAL's default orders only, without tidal terms. IMRPhenomD in MLX computes each binary's table in float32, so heavy binaries lose more to float32 there than in JAX. IMRPhenomXHM has LAL's defaults only (no mode arrays, release versions or multibanding).
  • Compilation time. IMRPhenomXPNR takes 15–20 s to compile, its gradient under a minute, and every array shape and batch size compiles separately. JAX's persistent compilation cache (jax_compilation_cache_dir) makes the cost one-off per machine. The tests use it; the package does not set it up.
  • Accelerators. The JAX versions ran on the CPU only. In JAX, both models run in float32 only through their pure functions, since the public functions and the conversions are float64; IMRPhenomXPNR's default model is accurate only in float64, which is slow on consumer GPUs. Neither model has been measured on a GPU through JAX. NRSur7dq4 and the lean IMRPhenomXPNR run on Apple GPUs through their MLX versions (section {{sec:nrsur}}, section {{sec:xpnr}}), which have limits of their own:
    • it is float32 only, since MLX has no float64 on the GPU;
    • they cannot be differentiated in forward mode (mx.jvp) or mapped with mx.vmap, which MLX does not carry through custom Metal kernels. They take batches themselves; NRSur7dq4's gradients are reverse mode, IMRPhenomXPNR's are its forward-mode Jacobian contracted in a custom VJP;
    • IMRPhenomXPNR in MLX has only the pure function at given frequencies (no LAL grids or conversions), depends on JAX to trace the model, and sizes its arrays with the binaries (the SpinTaylor steps, the grid of the PNR interpolants), so it reads sizes back from the GPU and does not run under mx.compile.
  • Forward-mode derivatives of IMRPhenomXPNR. A gradient costs one Jacobian column per parameter with a non-zero tangent, evaluated together. That is affordable for the twelve parameters of a binary (section {{sec:gradients}}), but it does not scale to derivatives with respect to the frequencies or to many other inputs. A reverse-mode path would need the loops with traced lengths rewritten with fixed bounds.
  • Discontinuities. The waveform inherits LAL's discrete choices. Gradient-based samplers near a regime boundary, such as in-plane spins near 1e-6, or a SpinTaylor integration that just fails, see the derivative of one side only.
  • Long waveforms. For light binaries from low frequencies the SpinTaylor splines have millions of knots and the conversions' Fourier transforms millions of samples. These are fixed-shape arrays held in memory, and both cost and compilation grow with them.
  • Multibanding. LAL's multibanding is not implemented (as in waveformrs).
